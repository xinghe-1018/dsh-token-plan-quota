# PLAN — 012 按模型用量的中文标签、占比与缓存命中

## 1. 现状

- `usageModelRow(model, copy)`（`lib/client.js`）把四类 token 拼成一行：`copy.usageSplit* + " " + formatTokens(...)`。
  zh 的四条 `usageSplit*` 文案**本身就是英文**（`input/output/cacheRead/cacheWrite`），所以模型行与总量卡在中文界面下露出英文。
- 总量卡 `usageSplitCell(label, value)` 只渲染「标签 + 数值」，没有占比，也没有命中率。
- `.tpq-usage-models{display:flex;flex-direction:column}` 没有高度约束，模型一多就把整页拉长。
- 006 的 FR-006 / SC-004 明令「屏内 0 个百分比」——当时的分母只有配额，属于宪法原则 I 的防卫；
  本次要加的是**实测 token 之间的构成比**，分母是我们自己数的 tokens，不涉及余量推估，因此按 FR-006 修订为「禁止配额百分比」而非「禁止一切百分比」。

## 3. 关键决策

1. **占比的分母用区间 tokens 总量，而不是 input+output。**
   四类 token 在 006 里是互不重叠的纯求和（`tokens = input+output+cacheRead+cacheWrite`），
   用总量作分母时四项加起来正好 100%，一眼能看出「这一段时间的用量构成」；
   若用 input+output 作分母，缓存那两项就被排除在外，读者会误以为缓存不算用量。
2. **命中率单独定义，不用构成比冒充。**
   命中率 = `cacheRead ÷ (input + cacheRead + cacheWrite)`：分母是 prompt 侧全部输入 token。
   它和「缓存命中占总用量 38%」是两件事，所以总量卡单独给一格「缓存命中率」，模型行末尾单独写「命中率 x%」，
   并在脚注里并排列出两条公式——不让同一个百分号在一屏里有两个没写明的分母。
3. **占比与命中率只来自实测 tokens，且必须带公式。**
   这是对 006「不显示百分比」的有意收窄：配额/余量百分比仍然禁止（原则 I 不动），
   但「本机数出来的 tokens 之间的比」是数据构成，不是对官方额度的估算。脚注写清「不是配额比例」。
4. **滚动只作用于模型列表。**
   整页滚动交给浏览器；模型卡是唯一会随模型数量无限变长的区块（本机已有 6 条以上）。
   固定约 4 行高 + 内部滚动，既保留排行可读性，也不把下方的官方对照条推到很远。
5. **命中率为 0 分母显示 `—`，不显示 0%。**
   `—` 表示「这段时间没有可缓存的输入」，0% 会被读成「缓存一次都没命中」，两者语义不同。
6. **悬停浮层保持绝对 token。** 011 的浮层契约是「某天用了多少」；加占比会把一个日桶的四个数再除一遍，
   信息重复且浮层变宽，本次不动它。

## 4. 备选与否决

- 否决「用堆叠条替代百分比数字」：能看构成，但读不出具体比例；用户明确要「占比」，数字 + 条都做又太重。
- 否决「占比放进悬停浮层」：与 FR-008 冲突，也超出用户所指的「下面的用量」。
- 否决「整屏滚动 / 虚拟列表」：模型数量在本地是十几条量级，虚拟列表属于过度设计。

## 5. 失败模式与对策

| 失败模式 | 对策 |
|---|---|
| 同一屏出现两个没写分母的 % | 脚注固定两条公式；命中率有独立标签 |
| 0 分母被写成 0% | `usagePercentText` 对 `base <= 0` 返回 null；渲染端显示 `—` |
| 极小占比显示成 0.0% | <0.1% 统一写 `<0.1%` |
| 百分比字面量散落回客户端代码 | guards 以白名单段标记切片，段外 0 个 % |
| 滚动容器键盘不可达 | `tabIndex=0` + `aria-label` + `:focus-visible` 描边 |
| 英文界面漏中文 / 中文界面漏英文标签 | COPY 双语键 + 整屏文本断言（en 无 CJK） |
| 旧 006 文档与新口径打架 | 006 原文保留、加一行「012 收窄」指向本规格 |
