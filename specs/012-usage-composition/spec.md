> 一，这些词请改成中文；二，我想直接看到缓存命中（命中率）和输入/输出各占多少；三，模型多的时候列表太长，给它一个滚动条。

截图里六条模型、第七条被截断——列表没有自己的滚动，只能让整页变长。数值本身早就是万/亿（中文界面），
真正没中文化的是**分项标签**（`input` / `output` / `cacheRead` / `cacheWrite`）。

## 2. 功能需求

- **FR-001 中文标签**：中文界面下四个分项写作 **输入 / 输出 / 缓存命中 / 缓存写入**
  （`cacheRead` 在本产品口径里就是「命中缓存后读取的 token」，沿用用户原话「缓存命中」）。
  英文界面写作 `input / output / cache hit / cache write`。数值继续走 `formatTokens`（中文 万/亿、英文 K/M/B）。
- **FR-002 缓存命中率**：每个模型行与总量卡显示 `cacheRead ÷ (input + cacheRead + cacheWrite)`，
  一位小数；分母为 0 时显示 `—`，不写 0%。这是 **prompt 侧缓存命中率**（缓存命中占「本可缓存的输入」的比例）。
- **FR-003 输入输出占比**：四类 token 各占**区间 tokens 总量**（= input+output+cacheRead+cacheWrite）的比例，
  一位小数；合计 100%。占比只在数值 > 0 时显示，避免每行挂一串 `(0%)`。
- **FR-004 口径与脚注**：占比与命中率都只由**本机实测 tokens** 相除得到，不是配额/余量百分比，
  不折算 Credits。屏内脚注写明两条公式与「数据构成，不是配额比例」。
- **FR-005 滚动条**：模型列表**自身**内滚动（约 4 行高），细滚动条、可用键盘滚动；
  模型少时不出现滚动条。整页布局与既有卡片顺序不变。
- **FR-006 口径修订**：006 FR-006 / SC-004 的「统计屏不显示百分比」收窄为
  **「不显示配额/余量百分比、不折算 Credits；本机实测 token 之间的构成比与命中率允许，且必须给出公式」**。
  006 文档保留原文并加一行指向本规格（历史规格不重写）。
- **FR-007 双语**：中英同时改；英文界面不出现中文，中文界面不出现四个英文标签（公式脚注里的英文键在英文界面照常）。
- **FR-008 零越界**：宿主、路由、配置键、出站主机、工具入参一律不动；悬停浮层仍只报绝对 token（011 契约不变）。
