# 020 按模型用量列表的滚动链（spec）

状态：**待做**（2026-11-14 接手，来源：用户观察）。plan / INTERFACE 由接手会话补写。

## 1 现象

在用量统计整页屏里，把鼠标放在「按模型用量」那块（模型明细列表）上滚轮滚动时，列表本身能滚；但**列表滚到底之后，外层整页视口不再往下走**。用户原话：「在"按模型用量"的窗口中滑动鼠标滚轮会发现不能向下滑，应该是两个滚动条冲突，鼠标放在子窗口中不会影响到原窗口，我希望在这个窗口滑动鼠标滚轮到底的时候可以继续向下滑动原窗口」。

## 2 根因（已由源码确认，非推断）

- 内层列表 `.tpq-usage-credits-models` 带 `overscroll-behavior:contain`。该值的语义就是**阻止滚动链**：内层到达边界后不再把滚轮事件交给祖先滚动容器。这与用户看到的现象完全一致。
- 外层整页视口 `.tpq-usage-viewport` 也带 `overscroll-behavior:contain`，但那是**故意**的：它防止视口到顶/到底后把滚动继续传给宿主页面（宿主外面两圈是 overflow:hidden，穿透会造成整页抖）。**这一处不要改**。
- 另有 012 时期遗留的 `.tpq-usage-models`（同样 contain），当前是否仍在用需要接手时确认；若仍在渲染路径上，一并处理。
- `.tpq-usage-chart-wrap` 是横向滚动（overscroll-behavior-x:contain），与本次竖向链无关，不要顺手改。

## 3 需求与验收

1. 鼠标在「按模型用量」列表内滚动时，列表先滚（现状保持）。
2. 列表到达**底部**后继续向下滚轮，外层整页视口同方向继续滚动；到达**顶部**后继续向上滚轮，外层视口继续向上滚动（双向链）。
3. 外层视口到边界时仍然不把滚动穿透给宿主页面（`.tpq-usage-viewport` 的 contain 保留）。
4. 键盘可达性不变：Tab 到列表后方向键/PageDown 仍能滚列表；焦点环仍走 018 的口径（不画整页白边、柱子不出 UA 框）。
5. 8px 细滚动条与 hover 交互不变。
6. 2D/3D 图、月份查询、悬停浮层等既有功能不受影响（回归底线）。

## 4 实现方向（供 plan 阶段取舍）

- 首选：把内层列表的 `overscroll-behavior:contain` 改为 `auto`（或直接删掉该声明，浏览器默认就是 auto）。一行 CSS 改动，行为即用户要的「滚到底继续滚外层」。
- 备选（不推荐）：在列表上挂轮询式 wheel 监听、手动把 delta 转给外层。理由：会与浏览器原生滚动、触摸板惯性、滚动条拖动打架，且回归面比一行 CSS 大得多。
- 验收必须有**真实滚轮证据**：CDP `Input.dispatchMouseEvent`（type wheel）连续滚动，记录「内层 scrollTop 递增 → 内层到顶 → 外层视口 scrollTop 开始递增」的序列；纯静态断言不足以证明链真的通了。

## 5 不做什么

- 不改外层视口的滚动手感、不加平滑滚动、不改 8px 滚动条样式。
- 不做「滚到底自动跳转到下一块」这类额外交互。
- 不碰宿主的滚动容器与焦点策略。
