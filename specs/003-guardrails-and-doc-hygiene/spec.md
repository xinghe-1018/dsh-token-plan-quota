# 003 — 门禁与文档卫生

来源：2026-09-18 的 `/retro`（对 001/002 两轮实践会话的复盘）。retro 的结论按交接规则只落三处——
`AGENTS.md`（反复出现的误解）、`workflow/PLAN.md`（反复出现的盲点）、以及**能机械化的一律做门禁**。
本规格是第三条的落点：retro 里 7 条候选中有 6 条可以变成确定性检查或去重，1 条（安装技能）已单独完成。

## 为什么现在做

两轮实践会话里，真正吃掉时间的三类问题**都不是判断失误，而是护栏本身的缺陷**：

1. **护栏误报**（最严重）：`npm run check` 在干净工作树上会假红。机制是**确定性**的——
   fixture 的痕迹守卫把整段 JSON 当字符串找子串，而快照里有 10–16 个由 `now` 派生的毫秒时间戳，
   某个时刻它们会巧合命中 4 位禁用串（`7943` / `9063`）。存在性有确定性复现点
   （`now=1789716103943` 时旧守卫必抛），**概率**则随墙钟窗口而变：三组独立测量分别是
   0.28%、1.10%、1.54%（口径见 `plan.md` 前提 1）。假红比没有检查更坏——它训练人忽略红灯，
   而本项目"红灯即停"的纪律正是靠这个可信度支撑的。
2. **同一语义两处实现**：README 链接存在 check 4 与 4b 两套抽取正则，窄的那套漏掉**引用式**与
   **HTML** 两种写法，又对**代码围栏里的示例**误报（001/002 的 Lens 1/2 各自独立发现过）。
3. **规则写在散文里而不在门禁里**：`workflow/PLAN.md` 早就写了"引用位置用标题锚点、不写行号"，
   但仓库里仍有大批 `file:line`，且 001 的评审已实测到行号过期。
   散文规则拦不住机械违规——这条是本项目自己的既定立场。

## 功能需求

- **FR-001**（误报消除）`assertFixture` 的"不含真实痕迹"守卫不得因**当前时钟**的巧合而失败。
  它必须仍能抓住真的把真实值写进 fixture 的改动（`remaining: 7943`、`Date`、`BigInt`、
  对象 key 里的痕迹都要报）。验收：行为矩阵含"应报"与"应放行"两端，并给出确定性复现点。

- **FR-002**（单源化）README 链接的抽取与分类只保留**一处实现**（`scripts/link-targets.mjs`），
  check 4（仓库内是否存在）、4b（是否随包发布）、第 10 项（截图契约）共用。
  抽取覆盖内联 / 徽标式 / 引用式 / HTML 四种写法（含带 title 与链接文字含方括号的形态），
  且先剥掉代码围栏与行内代码。**只有分类为 `relative` 的目标才允许碰文件系统**。

- **FR-003**（行号门禁）新增门禁：`workflow/**/*.md`、`specs/**/*.md`（**不含** `reviews/`）、
  `ROADMAP.md` 里不得出现 `文件:行号` 或 `文件#L行号` 形态的引用，改用可 grep 的锚点 / 符号名。
  代码围栏内的引用放行（它是命令输出或复现记录）。验收：行为矩阵 + 可证伪（在修复前必须报红）。

- **FR-004**（提交门禁）提供 pre-commit 钩子，把 `npm run check` 挂到提交前。
  验收：钩子在红树上真的拦住提交、在绿树上放行；且**默认不启用**（需显式 `core.hooksPath`），
  因为钩子是仓库级配置，不该由一次改动静默改变所有人的提交行为。

- **FR-005**（规则单源化）"新增或修改机械检查必须做行为矩阵且可证伪"这条规则曾有**三份副本**
  （`AGENTS.md`、`PLAN.md`、`REVIEW-CHECKLIST.md`）。收敛为"产出方（`PLAN.md`）+ 校验方
  （`REVIEW-CHECKLIST.md`）"两处，删掉 `AGENTS.md` 里那份——它每个会话都占上下文，却只是复述。

- **FR-006**（环境事实）本轮反复踩到的本机事实落到它们真正的消费位置：
  跨仓库都成立的那批（`pwsh` 实为 Windows PowerShell 5.1、写文件带 BOM、ANSI 解码、
  GitHub 取数通道间歇失败）进全局 `$DSH_HOME/AGENTS.md`；本仓库特有的（远端 SSH 别名、
  tag 与浅克隆、出图机前置）进 `workflow/ENVIRONMENT.md`。

- **FR-007**（常驻矩阵）三处门禁的**行为矩阵常驻化**（`test/guards.mjs`），含"应报 / 应放行"两端、
  "越界不变式"、"不得退化成二次方"、"入口判定不得静默失效"。
  理由：矩阵只写在规格文档里，会随会话结束失去约束力。

## 非目标

- **不改 `CHANGELOG.md`**：它记录的是已发布的历史，其中的行号引用是当时的现场，改它就是篡改历史。
- **不改 `reviews/` 下的评审报告**：那是"当时看到了什么"的冻结证据，允许其行号随代码漂移。
  门禁按**任何层级的 `reviews/` 目录**豁免——豁免的是"记录"这一类东西，不是某个具体路径。
- **不改源码注释里的行号**（`scripts/shots/*.mjs`、`scripts/check-docs.mjs` 里按行号写的那些）：
  那是实现者对自己刚看过的位置的就地批注，腐烂半径小、且不影响对外承诺。
- **不把 `ROADMAP.md` 的历史段落逐字重写**：只把引用形态从行号换成锚点，结论不动。
- **不新增依赖**：钩子与门禁都用 Node 标准库（宪法 IV）。
- **不改任何宪法原则**：但按宪法自身的修订程序把 VI 章那条陈旧的 `npm run check` 组成清单
  同步为 **v1.0.1（PATCH）**——清单是"订阅"而非规则本身，门禁集合变了它就该跟着变，
  否则 `AGENTS.md` 所称的"判定口径的权威"这一份会最先漂。

## 与既有规格的关系

001 与 002 的结论与工件保持原样（除 FR-003 要求的引用形态）。本规格是它们的**护栏层**补充：
001/002 修的是"文档说的和代码不一致"，003 修的是"发现不一致的机制本身不可靠"。
