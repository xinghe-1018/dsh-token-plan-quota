# 003 — 计划

## 0. 修订

- 初版思路（被推翻）：FR-001 一开始想"把 `now` 钉成一个固定值再断言"。
  否决理由见「备选方案」——那等于让守卫去验一个**真实出图时不存在**的 payload，
  是用测试的便利换取守卫的失明。

## 1. 非目标

见 `spec.md`「非目标」。此处重申最容易被顺手越界的那条：
**不重写 `specs/**/reviews/**` 里的行号**——它们是冻结证据，允许漂移（这正是"评审期间冻结工作树"规则存在的原因）。

## 2. 前提（逐条核验，✅ = 已用命令/代码核实）

| # | 前提 | 核验 | 结果 |
|---|---|---|---|
| 1 | `npm run check` 在**干净工作树**上会假红，且不是偶发幻觉 | 干净树连跑：`check-docs` 单跑 20 次 → 1 次红；`npm run check` 首跑即红。构造性复现：`now=1789716103943` 时 `updatedAt=now-12000=1789716077943` 含禁用串 `7943` → `assertFixture` 抛错。按派生偏移在 600000ms 窗口内穷举：2279 个时刻会冲突，单张 p≈0.0038，每轮 10 张 → **每轮假红率≈3.73%** | ✅ |
| 2 | 假红的机制是"整段 JSON 当字符串找子串"，而 `now` 派生的**13 位毫秒时间戳**会巧合命中 4 位禁用串 | `fixture.mjs` 里 `const now = options.now ?? Date.now()`，10 个字段由 `now±常数` 派生；`assertFixture` 用 `JSON.stringify(snapshot).includes(banned)`。把 `now` 冻结后穷举即可稳定复现 | ✅ |
| 3 | CI 也在跑这条检查，所以假红会传染到每个 PR | `.github/workflows/ci.yml` manifest job 的 `README claims match the code` 步骤跑 `check-docs.mjs` | ✅ |
| 4 | README 链接目前有**两套**抽取实现，窄的那套漏三种写法 | `check-docs.mjs` 第 4 项内联 `\]\((?!https?:…)`；4b 在 100–103 行另有四套正则。Lens 1/2 在 002 轮各自独立报过同一处 | ✅ |
| 5 | "机械检查必须做行为矩阵且可证伪"这条规则有**三份副本** | grep：`AGENTS.md`（Conventions 末条）、`workflow/PLAN.md`（第 77–78 行测试计划要求）、`workflow/REVIEW-CHECKLIST.md`（Lens 1 条目） | ✅ |
| 6 | 仓库目前**没有任何提交门禁** | `Test-Path .githooks` = False；`git config --get core.hooksPath` 为空 | ✅ |
| 7 | 行号引用在门禁范围内确实存在（不是只存在于 reviews） | 全仓 grep `文件:行号` 命中 50 处；其中 `ROADMAP.md` 3 处、`specs/001` 的 plan/qa/tasks 6 处属范围内。确数以新门禁的首次输出为准 | ✅ |

**前提 1 的意义**：这不是"偶发不稳定"，而是**可复现的误报**。`AGENTS.md` 与 `PLAN.md` 都写了
"漏检或误报的检查比没有检查更糟（假安全感）"——所以这一条是本规格的第一优先级，而非附带修复。

## 3. 备选方案（各自被否决的理由）

### FR-001 误报消除

| 方案 | 否决理由 |
|---|---|
| A. 断言前把 `now` 钉成固定值 | 真实出图用的是真实时钟；钉死后守卫验的是**另一个 payload**，从此对"截图里真的出现真实痕迹"失明 |
| B. 干脆不扫数字（只扫字符串） | 丢掉了最该抓的一类：fixture 里硬编码 `remaining: 7943` 就是真实余额泄漏 |
| C. **逐叶扫描 + 时钟整数豁免**（采用） | 字符串仍按子串查（用户名、盘符、日期、格式化金额）；数字按字符串查，但 `|n| ≥ 1e12` 的整数视为时钟毫秒值豁免——真实痕迹（余额、Credits、token 数）都不在那个量级 |
| D. 把禁用串换成更长的组合（如余额的完整小数位） | 治标：任何 4 位串都能被 13 位时钟命中，换串只是换一个巧合点 |

### FR-002 单源化

| 方案 | 否决理由 |
|---|---|
| A. 把 4b 的正则复制给第 4 项 | 正是"同一语义两处实现"的复发，下一次改一处忘一处 |
| B. **共用一个 `extractLinkTargets()`**（采用） | 一处实现，两个消费者（仓库内存在 / 随包发布） |
| C. 只保留 4b、删掉第 4 项 | 4b 在 `files` 缺失时整段跳过；第 4 项是那个情况下的唯一防线 |

### FR-003 行号门禁

| 方案 | 否决理由 |
|---|---|
| A. 把 `PLAN.md` 里那句规则写得更强 | 已被证伪：规则早就在，仓库里仍有 50 处引用。"散文规则拦不住机械违规"是本项目既定立场 |
| B. **新门禁 + 保留 `PLAN.md` 那句作为产出方说明**（采用） | 产出（PLAN）与校验（门禁 + Lens 1）配对，符合 retro 的"机械违规做门禁" |
| C. 门禁也扫源码注释 | 非目标：实现者对自己刚看过的位置的就地批注，腐烂半径小；且会把改动面从 9 处扩到 50 处 |

### FR-004 提交门禁

| 方案 | 否决理由 |
|---|---|
| A. 装好钩子并直接 `git config core.hooksPath .githooks` | 一次改动静默改变所有协作者的提交行为；且钩子是本地配置，仓库里"配好了"的假象会误导 |
| B. **提供 `.githooks/pre-commit` + 文档里一行启用命令**（采用） | 想用的人一行启用；不想用的人不受影响。默认不启用是**刻意的**，写进文档而非靠猜 |
| C. 只依赖 CI | 假红的代价在 CI 上被放大到每个 PR；本地钩子让红灯在提交前出现 |

### FR-005 / FR-006

- FR-005：三个副本收敛为两处（产出方 `PLAN.md` + 校验方 `REVIEW-CHECKLIST.md`），删 `AGENTS.md` 那份。
  保留 `AGENTS.md` 的 `workflow/PLAN.md` 指针即可——它已经在那里。
- FR-006：见「落点决策」——PowerShell 引号是**行为规则**（要每次生效）→ 全局 `AGENTS.md`；
  GitHub 通道是**环境查表**（只在本机取数时用）→ 同一处（它是本机事实，且有既有的"本机环境事实"小节）。
  仓库内的 `workflow/ENVIRONMENT.md` 只放**本仓库**的环境事实（远端 SSH 别名、CDP 出图前置、`DSH_HOME` 隔离），
  并由 `workflow/README.md` 指向。

## 4. 失败模式（agent 的固定翻车方式 → 本规格的接住机制）

| 失败模式 | 长什么样 | 接住机制 |
|---|---|---|
| **新门禁自己误报** | 刚加的检查像 FR-001 一样假红 | 每条新/改门禁的测试计划必须含"应当放行"用例；FR-001 的行为矩阵就是被误报打脸后的产物 |
| **检查写了但没接线** | 新脚本只加进 `npm run check`，忘了 `ci.yml` | 计划步骤里把"接进两处"写成同一步；Lens 3 核 diff 文件清单 |
| **修引用时改坏语义** | 把「文件 + 行号」换成锚点时顺手把结论也改了 | 只换形态不改结论；Lens 1 逐条复核替换后的引用仍指向同一事物 |
| **顺手扩大范围** | 顺手把 reviews/ 与源码注释也扫了 | 非目标在 `spec.md` 与本文第 1 节各写一次；门禁的白名单是显式的 |
| **假绿** | 新门禁在范围内一个违规都找不到，其实正则写错了 | 可证伪：在修复前提下车必须报红（本计划记录实际红线数） |

## 5. UI 状态

不适用：本规格不含 UI 改动。FR-001 只改**守卫的判定方式**，`makeSnapshot()` 的输出不受影响——
这一点由测试计划 T6（固定 `now` 下改动前后 JSON 逐字节相同）证明，也是"截图不需要重拍"的依据。

## 6. 测试计划

> 本规格新增/修改了机械检查，所以下面每条都带**行为矩阵**与**可证伪性**（`PLAN.md` 的要求）。

### T1 — FR-001 行为矩阵（`assertFixture` 的痕迹守卫）

| # | 输入 | 期望 |
|---|---|---|
| 1 | 固定 `now`，`makeSnapshot({now, variant, lang})` × 5 变体 × 2 语言 | 全部放行 |
| 2 | **冲突时刻** `now=1789716103943`（`updatedAt` 含 `7943`） | 放行（修复前**报红**，这就是基准证据） |
| 3 | 把某张卡改成 `remaining: 7943`（真实余额） | 报红 |
| 4 | 加一个字符串字段 `"39.91 CNY"` | 报红 |
| 5 | 加 `OMEN` / `C:\` / `.scratch` 字符串 | 报红 |
| 6 | 卡里放 `lastAt: 1789716077943`（时钟，落在卡内） | 放行 |
| 7 | 数字 `7939999999999`（≥1e12，时钟量级） | 放行 |

**可证伪**：在 `HEAD` 的 `fixture.mjs` 上跑用例 2 必须抛错；修复后必须放行。输出留档。

### T2 — FR-002 行为矩阵（链接抽取单源化）

四种写法 × 两个消费者，共 8 格；另加"代码围栏内不认"与"远程/锚点/mailto 不认"两格。

| 写法 | 第 4 项（仓库内存在） | 4b（随包发布） | 修复前 |
|---|---|---|---|
| 内联 `[x](a.md)` | 认 | 认 | 两项都认 |
| 带 title `[x](a.md "t")` | **认** | 认 | 第 4 项不认 |
| 引用式 `[x][r]` + `[r]: a.md` | **认** | 认 | 第 4 项不认 |
| HTML `<a href="a.md">` | **认** | 认 | 第 4 项不认 |
| 围栏里 ```[x](a.md)``` | 放行 | 放行 | 4b 放行、第 4 项误报 |
| `https://` / `#frag` / `mailto:` | 放行 | 放行 | 放行 |

**可证伪**：临时把 README 的一条链接改成指向 `workflow/README.md`（不随包发布但仓库内存在）→
第 4 项放行、4b 报红；改成指向 `workflow/nope.md` → 两项都报红。

### T3 — FR-003 行为矩阵（行号门禁）

| # | 路径 | 内容 | 期望 |
|---|---|---|---|
| 1 | `workflow/x.md` | 文件 + 行号 | 报红 |
| 2 | `specs/004-x/plan.md` | 文件 + 行号 | 报红 |
| 3 | `specs/001-…/reviews/lens-1.md` | 文件 + 行号 | **放行**（冻结证据） |
| 4 | `CHANGELOG.md` | 文件 + 行号 | 放行（已发布历史） |
| 5 | `workflow/x.md` | 写在代码围栏里 | 放行（命令输出/复现记录） |
| 6 | 任意允许文件 | 不带行号的文件名、项目条目编号 | 放行 |
| 7 | `ROADMAP.md` | 文件 + 行号 | 报红 |

具体样例放进围栏——第 5 行要证明的豁免正好由这段自己证了（`test/guards.mjs` 用同样的形态做常驻矩阵）：

```text
应报红：见 lib/index.js:44 ／ README.md:239 ／ lib/index.js:368-376 ／ 续写形态 `:1189`
应放行：见 lib/index.js 的 autoDetect ／ 第 1–9 项 ／ http://127.0.0.1:3080 ／ 9:00 ／ 比例 1:2
```

**可证伪**：在**未修 backlog** 的树上跑（实测）→ 报出 **26 条**红线、退出码 1；修完必须为 0 且退出码 0。

### T5 — FR-005 / FR-006

`grep` 断言：`AGENTS.md` 不再含该规则正文；`PLAN.md` 与 `REVIEW-CHECKLIST.md` 各含一份；
`AGENTS.md` 仍在**一页以内**（行数 ≤ 60）。

### T6 — 回归隔离

固定 `now` 下，改动前后 `JSON.stringify(makeSnapshot({now, variant, lang}))` **逐字节相同**
（5 变体 × 2 语言）。用于证明 FR-001 只碰了守卫、没碰数据，截图无需重拍。

### T7 — 全量

`npm run check` 全绿，且在**最后一次编辑之后**跑出来；另外连跑 30 次证明假红已消除
（修复前同窗口的期望假红数 ≈ 1，见 T1 用例 2）。

## 7. 步骤

1. FR-001：`scripts/shots/fixture.mjs` 的痕迹守卫改为逐叶扫描 + 时钟整数豁免。
