# 007 — 按日期区间查用量（from / to）

- **状态**：已实现前的计划（Context → Plan 已完成）
- **上游**：006 用量统计（本实例实测）已上线；本规格只加"按具体日期区间查询"这一件事
- **一句话**：把"近 N 天"补成"从几号到几号"，其余口径不动（绝对 token、本机实测、不折算 Credits）

## 1. 用户故事

> 我想看 **2026-09-01 到 2026-09-30** 一共用了多少 token，而不是只能选"近 30 天"。

现在的 `?days=N` 只能表达"以今天为终点往前数 N 天"。跨月、跨账期、排查某次事故对应的那几天，
都需要**两端都由用户指定**的区间。

## 2. 功能需求

- **FR-001 查询参数**：`GET /token-plan-quota/usage?from=YYYY-MM-DD&to=YYYY-MM-DD`，两端闭区间。
- **FR-002 优先级**：`from`/`to` 同时出现时优先于 `days`/`range`；只给一个 → 400（不猜另一端）。
- **FR-003 校验**：格式非法、`from > to`、`from` 在今天之后 → 400 `usage-bad-range`；
  跨度超过 `usageBackfillDays`（默认 365）→ 400 `usage-range-too-long`（带 `maxDays`）。
- **FR-004 未来端点**：`to` 晚于今天时**夹到今天**（`range.to` 回今天），不报错也不返回未来空桶。
- **FR-005 桶粒度**：跨度 ≤ 62 天按日桶，> 62 天按本地周一为界周桶；**桶必须恰好铺满区间**，
  首桶从 `from` 起、末桶到 `to` 止（周桶允许首末不足 7 天）。
- **FR-006 区间标识**：响应 `range = { kind: "custom", days, from, to }`，`days` = 闭区间天数。
- **FR-007 界面**：天数预设旁新增「自定义」入口，展开起止日期两个原生日期框 + 查询按钮；
  非法输入在屏内给一行提示、**不发请求**；查询成功后标题显示「2026-09-01 至 2026-09-30 · 30 天」，
  同一天则显示「2026-09-15 当天」。
- **FR-008 口径不变**：只有绝对 token；脚注补一句「仅统计本机 DSH 发出的调用」。

## 3. 非目标

- 不做"按时段/按小时"的查询（会话索引本身按小时记，但屏上没有可用的时间轴交互，属于另一件事）。
- 不做跨实例/账号级用量（本机看不到别的设备发起的调用；账号侧只有比例，没有 token）。
- 不引第三方日期库：`YYYY-MM-DD` 与本地日历的换算现有 `dayKey`/`dayKeyToDate` 已够用。

## 4. 成功判据

- **SC-001** 同一区间用 `days` 与 `from/to` 查，当日桶粒度下逐桶数值完全一致（同源校验）。
- **SC-002** 周桶区间：首桶 `from` 等于用户给的 `from`（不早于它），末桶 `to` 等于用户给的 `to`。
- **SC-003** 六类非法输入各回 400 且错误码固定（缺一端、格式错、起点晚于终点、起点在未来、
  跨度超限、非法月份/日期）。
- **SC-004** 屏上非法输入零请求（用 fetch 计数器断言）。
- **SC-005** 中英两种界面都不出现百分比与 Credits；脚注含"仅统计本机"。
