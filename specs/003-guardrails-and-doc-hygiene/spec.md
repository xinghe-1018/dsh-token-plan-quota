# 003 — 门禁与文档卫生

来源：2026-09-18 的 `/retro`（对 001/002 两轮实践会话的复盘）。retro 的结论按交接规则只落三处——
`AGENTS.md`（反复出现的误解）、`workflow/PLAN.md`（反复出现的盲点）、以及**能机械化的一律做门禁**。
本规格是第三条的落点：retro 里 7 条候选中有 6 条可以变成确定性检查或去重，1 条（安装技能）已单独完成。

## 为什么现在做

两轮实践会话里，真正吃掉时间的三类问题**都不是判断失误，而是护栏本身的缺陷**：

1. **护栏误报**（最严重，本轮实测）：`npm run check` 在干净工作树上会以约 **3.7%** 的概率假红
   （见 `plan.md` 前提 1 的实测）。假红比没有检查更坏——它训练人忽略红灯，而本项目
   "红灯即停"的纪律正是靠这个可信度支撑的。
2. **同一语义两处实现**：README 链接存在 check 4 与 4b 两套抽取正则，窄的那套漏掉三种惯用写法
   （001/002 的 Lens 1/2 各自独立发现过）。
3. **规则写在散文里而不在门禁里**：`PLAN.md` 早就写了"引用位置用标题锚点、不写行号"，
   但仓库里仍有 50 处 `file:line` 引用，且 001 的评审已经实测到行号过期。
   散文规则拦不住机械违规——这条是本项目自己的既定立场。

## 功能需求

- **FR-001**（误报消除）`assertFixture` 的"不含真实痕迹"守卫不得因**当前时钟**的巧合而失败。
  它必须仍能抓住真的把真实值写进 fixture 的改动（`remaining: 7943` 这类必须报红）。
  验收：构造 4 个应报用例 + 2 个应放行用例（含本轮实测的冲突时刻），逐个给出实际输出。

- **FR-002**（单源化）README 链接的抽取只保留**一处实现**，check 4（仓库内是否存在）
  与 4b（是否随包发布）共用它。抽取必须覆盖内联 / 带 title / 引用式 / HTML 四种写法，
  且先剥掉代码围栏与行内代码。验收：原先只有 4b 认得的三种写法，现在第 4 项也认得。

- **FR-003**（行号门禁）新增门禁：`workflow/**/*.md`、`specs/**/*.md`（**不含** `reviews/`）、
  `ROADMAP.md` 里不得出现 `文件:行号` 形态的引用，改用可 grep 的锚点 / 符号名。
  代码围栏内的引用放行（它是命令输出或复现记录）。验收：行为矩阵 + 可证伪（在修复前必须报红）。

- **FR-004**（提交门禁）提供 pre-commit 钩子，把 `npm run check` 挂到提交前。
  验收：钩子在红树上真的拦住提交、在绿树上放行；且**默认不启用**（需显式 `core.hooksPath`），
  因为钩子是仓库级配置，不该由一次改动静默改变所有人的提交行为。

- **FR-005**（规则单源化）"新增或修改机械检查必须做行为矩阵且可证伪"这条规则目前有**三份副本**
  （`AGENTS.md`、`PLAN.md`、`REVIEW-CHECKLIST.md`）。收敛为"产出方（`PLAN.md`）+ 校验方
  （`REVIEW-CHECKLIST.md`）"两处，删掉 `AGENTS.md` 里那份——它每个会话都占上下文，却只是复述。

- **FR-006**（环境事实）本轮反复踩到的两条本机事实（PowerShell 把中文弯引号当字符串定界符；
  GitHub 取数通道被本机代理劫持）落到它们真正的消费位置。

## 非目标

- **不改 `CHANGELOG.md`**：它记录的是已发布的历史，其中的行号引用是当时的现场，改它就是篡改历史。
- **不改 `specs/**/reviews/**`**：评审报告是"当时看到了什么"的冻结证据，允许其行号随代码漂移；
  这正是 `REVIEW-CHECKLIST.md` 里"评审期间冻结工作树"那条规则存在的原因。
- **不改源码注释里的行号**（`scripts/shots/*.mjs` 等）：那是实现者对自己刚看过的位置的就地批注，
  腐烂半径小；本轮只收口文档层（FR-003 的范围就是这么定的）。
- **不 bump 宪法版本**：本规格没改变任何宪法原则，只让既有原则更可执行。
- **不新增依赖**：钩子与门禁都用 Node 标准库（宪法 IV）。
- **不把 `ROADMAP.md` 的历史段落逐字重写**：只把其中的引用形态从行号换成锚点，结论不动。

## 与既有规格的关系

001 与 002 的结论与工件保持原样（除 FR-003 要求的引用形态）。本规格是它们的**护栏层**补充：
001/002 修的是"文档说的和代码不一致"，003 修的是"发现不一致的机制本身不可靠"。
