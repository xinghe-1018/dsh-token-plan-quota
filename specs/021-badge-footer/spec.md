# 021 徽标小窗底部操作被截半（spec）

状态：**待做**（2026-11-14 接手，来源：用户观察 + 一张未能读取的截图）。plan / INTERFACE 由接手会话补写。

## 1 现象

输入框上方的额度徽标弹层（小窗）里，最下面的「用量统计」入口被挤到面板底缘、**只露出一半**。用户原话：「另外小窗口出现了用量统计被挤在最下面剩一半的情况」。

## 2 现有结构（源码事实）

- 弹层结构：`.tpq-panel` → `.tpq-body`（`max-height:min(52vh,460px);overflow:auto`；悬浮态改成 `max-height:none;height:100%`）。
- `.tpq-body` 里的顺序：标题栏 → 吞吐块（可选）→ 每张额度卡 → **「更新/刷新时间」按钮 `.tpq-updated`** → **「用量统计」入口 `.tpq-usage-entry`**。这两个按钮是 `.tpq-body` 的**最后两个子元素**，跟着内容一起滚动。
- 因此只要内容高度超过 `.tpq-body` 的可视高度（默认锚定态被 `min(52vh,460px)` 或「徽标上方可用空间」夹住；悬浮态被用户拖小），最后这两个按钮就落在折叠线以下——露出半行是它的自然结果。这也解释了为什么「平时看着正常、拖小一点就半截」。
- 相关状态持久化：拖拽/缩放后的矩形存 localStorage（`loadFloatBox`/`saveFloatBox`），所以用户一旦把面板拖小，这个半截状态会跨刷新保留。

## 3 需求与验收

1. 面板底部这两个操作（更新按钮 + 用量统计入口）**固定在面板可视区底部**，内容在它们上方滚动；任何面板高度下都完整可见，不出现「露半行」。
2. 三种情形都要验：默认锚定态、悬浮态拖到最小高度、内容显著超过容器（多张额度卡 + 吞吐块）。
3. 固定底栏必须有**不透明背景**（不能透出下面滚动的卡片文字），与面板底色同源（用主题变量，不要硬编码 #fff/#1e1e1e）。
4. 底栏不能盖住右下角 18×18 的缩放手柄：手柄仍可点击、缩放仍生效。
5. 键盘与读屏：两个按钮仍可 Tab、focus ring 仍是品牌色 2px；「用量统计」仍只在 `usageStats !== false` 时出现。
6. 中英两种界面、深浅两种主题都验；面板滚动条仍是 auto，不新增横向溢出。

## 4 实现方向（供 plan 阶段取舍）

- 首选：把两个按钮包进一个 `.tpq-panel-foot` 容器，`position:sticky; bottom:0`（在 `.tpq-body` 这个滚动容器里粘底）+ 负外边距铺满整宽 + 面板底色 + 上边细描边。改动集中在 Badge 的 children 结构与一段 CSS。
- 备选（结构更干净但要动布局）：把底栏移出 `.tpq-body`，面板改成「`.tpq-body` 滚动 + `.tpq-foot` 常驻」两段式；代价是悬浮态 `height:100%` 与 resize 手柄的两处既有约定都要重新对齐，回归面更大。
- 无论哪条：**先复现再改**。用 CDP 打开徽标弹层，量 `.tpq-usage-entry` 的 rect 与 `.tpq-body` 的 clientHeight/scrollHeight（悬浮态再把面板缩到最小高度），拿到「按钮底边超出可视底边」的数字证据。

## 5 不做什么

- 不改额度卡内容与顺序、不改吞吐块。
- 不改拖拽/缩放的手势与持久化格式。
- 不做「内容自动收起」「折叠面板」这类新交互。
