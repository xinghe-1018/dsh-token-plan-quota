# 006 — 最近用量统计（tokens，非 Credits）

来源：2026-11-13 会话。用户要求「新增一个额度统计功能，统计最近的额度用量，用 tokens 来表示，不是用 qwen 自家的 credits 显示」，
并在三选项里选定：**独立的大屏**、**读会话记录回填最近 30 天**、**先出计划工件再实现**。
本规格要解决的是「最近用了多少 token」这个问题现在**没有数据面**（账号本只有自然月分桶与 7 天窗口锚点，答不了今天/近 7 天/近 30 天），
而不是「再做一个官方额度卡」。

## 为什么现在做

1. **现有数字答不了用户最常问的问题。** 千问 Token Plan 卡给的是 Credits 百分比（per5Hour/per1Week/per1Month），
   用户明确不要；「本实例实测用量」月卡只有当月累计，没有按天曲线，看不到趋势，也看不到今天。
2. **数据本来就已经存在，只是没折叠成天。** DSH 宿主把每次调用的真实 usage（input / output / cacheRead / cacheWrite）
   记进会话事件流；dsh-service 曾用同一批事件建过按小时索引（本机 160 个会话、直接按天聚合可用），证明这条路可行且不碰消息内容。
3. **口径风险必须先定死。** 这是「实测」（只统计经过本 DSH 实例的调用），按宪法原则 I：不派生百分比、不画余量条、不折算 Credits。
   先写规格，是为了让实现与评审都拿同一条口径去核，而不是做完再解释。

## 功能需求

- **FR-001**（数据来源与口径）统计数字**只来自本实例的会话记录**（宿主 sessionPersistence 事件流），
  即每一次经过本 DSH 实例的真实调用携带的 `usage`。不读供应商额度接口、不含 Credits、不估算、不按历史外推。
  每条计入 input / output / cacheRead / cacheWrite 四类 token 与 steps。
  验收：抽样对账——同一批会话，(索引日合计) 等于 (事件流逐条 sum)；对外文案标注「本实例实测」。

- **FR-002**（按天分桶 + 增量索引）新增独立索引（默认 `$DSH_HOME/token-plan-quota.usage-index.json`），
  按**本地日**（用户时区，非 UTC）分桶：每桶 totals（四类 token + steps + calls）+ models[provider/model]。
  每个会话记录 `revision` 与 `lastSeq`；首次启用回填最近 30 个自然日（含今日），之后从 `lastSeq + 1` 起增量读；
  同一事件只计一次（幂等）。
  验收：连续两次刷新 totals 不变；删索引重建结果与首建一致；revision 未变的会话不重读。

- **FR-003**（范围与聚合）支持预设 今日 / 近 7 天 / 近 30 天 / 近 90 天（均含今日），以及**自定义天数 1..`usageBackfillDays`**。
  返回：区间总分（四类 token + steps + 调用次数）、逐桶序列（**缺失日补 0，不跳格**）、按模型 Top（含 provider）。
  桶粒度：`days ≤ 62` 按自然日；`> 62` 按周聚合（周一为界，末桶可不足 7 天），轴标注「每 7 天」——服务端只回桶，
  客户端两种图形共用同一组桶。验收：区间总分 == 逐桶之和 == 各模型之和（同一快照内三条恒等式）。

- **FR-004**（只读统计接口）新增 `GET /token-plan-quota/usage?range=today|7d|30d&days=N`，
  返回 `{generatedAt, range, granularity, buckets:[{from,to,label,totals,models}], totals, models, source:{kind:"session-index", veracity:"measured"}, coverage:{from,to,sessions,indexedSessions,skipped}, emptyReason?}`；
  索引构建中/不可用时返回结构化状态（带 `emptyReason` / `hint`），不 500、不静默空数组。
  验收：host 路由测试断言字段形状与四类 token 映射；响应内不含任何消息文本、请求体、请求头或凭据。

- **FR-005**（独立统计屏）从额度徽标小窗或侧栏入口打开**主区整页**（宿主官方 `main` 座位：替换会话主区、侧栏保留，
  不新开窗口、不新开路由），内容：标题与关闭、**天数选择**（预设今日/7/30/90 + 自定义 1..365）、
  **图表模式切换 2D / 3D 柱状图**、总分卡、按模型列表、数据源脚注。
  两种图形共用同一组桶与同一线性刻度（柱高 = 桶 tokens / 区间最大值，是可视化缩放、**不显示百分比文本**）；
  3D 为固定角度等轴投影，**无透视缩短、无近大远小**，只换投影不换数据（详 plan §5.5）。
  必须有 空 / 加载中 / 首次回填中 / 错误 四种状态；关闭后回到原会话，不打断输入。
  验收：client 测试对四种状态、两种图形切换、天数参数做断言；375px 与 768px 窄视口不横向溢出（PLAN §7 的口径）。

- **FR-006**（不派生、不折算）统计屏**不画余量条、不显示百分比、不出现 Credits 单位**；
  只有 token 计数、时间范围与「实测」标注。代码里不得存在 credits→tokens 的换算。
  验收：client 断言渲染文本不含 `%` 与 `Credits`；评审 grep 不到换算函数。

- **FR-007**（隐私边界）索引文件只存：日/小时键、四类 token 计数、steps、provider/model id、会话 id 与 revision/lastSeq。
  不落用户消息、系统提示、工具输出、请求头、Cookie、密钥。日志与错误信息同样只带计数与 id。
  验收：guards 断言索引 schema 白名单；测试快照内不出现会话内容；原则 II 的三份 lens 各核一遍。

- **FR-008**（配置）新增 `usageStats`（开关，默认 true）、`usageIndexPath`、`usageBackfillDays`（默认 365，即索引保留天数与天数选择上界；
  首轮同步扫全量会话，保留多少天只影响落盘桶数与可选窗口，不影响首轮耗时）。
  DEFAULTS 键数变化必须同步两份 README 与正文计数句（check-docs 1/6/8）。
  验收：check-docs 全绿，配置表行数 = DEFAULTS 键数 + 1。

- **FR-009**（模型工具）`token_plan_quota` 增加 `action=usage`（可选 `days`），返回文本摘要 + 结构化 totals；
  不新增任何网络请求。验收：buildQuotaTool 测试断言 enum 与输出形状。

- **FR-010**（文档同源）同一次改动内更新：README.md / README.en.md（功能段、配置表、路由表、DEFAULTS 计数、三套测试项数）、
  CHANGELOG、`docs/upstream-contracts.md`（新增「会话事件 → 用量」这一条契约，标明非上游、属本实例实测）、
  截图清单（`check-docs.mjs` 的 SCREENSHOTS 硬编码 + requiredImageRefs）与脚本生成的统计屏截图。
  验收：`npm run check` 七步全绿，且是最后一次编辑之后跑出来的输出。

- **FR-011**（降级与失败模式）宿主未提供 sessionPersistence、或某会话不可读（半写/损坏/权限）时：
  跳过该会话并计数，统计屏显示「部分会话未覆盖（N 个）」；完全不支持时降级为「本进程启动以来」并给诊断，
  不静默返回 0。验收：host 测试用假 persistence 断言两条降级路径与诊断字段。

## 非目标

- **不做任何成本/金额估算**（不引入 ¥/$、不乘单价、不折算 Credits）。本插件在 ROADMAP 里已声明不是请求级成本统计；
  金额与单价归 `dsh-cost-meter` 一类工具。
- **不读供应商侧数据反推用量**：不使用千问控制台比例、BALANCE 余额或任何 Credits 数字参与本次统计。
- **不改现有官方卡与「本实例实测用量」月卡的语义**：原月账本（`token-plan-quota.usage.json`）继续按自然月累加，
  新索引是并存的另一份数据面；两者口径相同（都属实测）但聚合粒度不同。
- **不跨机器/跨 CLI 汇总**：只统计本 DSH 实例的会话记录；不读其它 CLI 的登录态或用量文件。
- **不回显消息内容**：统计屏不提供「点开某天看当时聊了什么」，索引里也没有这些数据。
- **不新增第三方依赖、不引入构建步骤**（宪法 IV）；浏览器半边仍是手写 bundle。
- **不做云端同步/多端合并**；不修改 `docs/images/` 里既有的 13 张截图。

## 与既有规格的关系

001–004 修的是文档与门禁（描述和代码不一致、图资产入库）；005 修的是徽标跟随当前模型。
006 是**第一个新增数据面的功能规格**：它不改变既有任何卡的取数与展示，只在旁边加一份「按天折叠的实测用量」，
并把它呈现为独立屏。因此它的门禁必须同时落三处：host 单测（折叠恒等式）、client 渲染断言（四种状态）、
`check-docs`（配置/计数/截图清单）——这也是本次改动面比 004/005 大的原因。

## 成功标准（可度量）

- **SC-001** 装上后首次打开统计屏，≤3s 内看到今日与近 7 天数字（30 天回填可在屏上显示进度）。
- **SC-002** 在同一份会话事件流上，索引 totals 与逐条累加**完全相等**（0 误差，含 cacheRead）；重复构建幂等。
- **SC-003** 全量回填本机现有 160 个会话（约 30 天）耗时 < 5s（实测记录写进 plan 的 QA 段）。
- **SC-004** 统计屏与接口中 **0 个百分比、0 个 Credits 字样**（除说明「不折算 Credits」的脚注外）。
- **SC-005** `npm run check` 七步全绿；三套测试项数与 README 声称一致；运行时不新增任何出站主机。
- **SC-006** 同一区间下 2D 与 3D 的柱高由**同一个比例函数**算出（只差投影），3D 柱高与桶值成线性、无透视；
  两种图形的（柱高 / 区间最大值）之比逐桶相等（客户端测试断言）。
- **SC-007** 天数输入 0 / 366 / 非数字时不发出请求或夹到 1..365，界面回填实际使用的天数；超过 62 天自动按周出桶（周一起界）。

## 待澄清 / 由 plan 决定

- 独立屏的挂载面（已定）：宿主 `main` 整页座位 + `sidebar.panellist` 入口 + `ctx.layout.selectPanel(id)`；portal 覆盖层降为座位缺失时的回退（已核，见 plan 前提 10）。
- 索引文件是否与月账本合并（倾向：**不合并**，索引写独立文件，避免改动既有账本契约与 reset 语义）。
- 回填的触发时机：插件启动即后台跑，还是首次打开统计屏时跑（倾向：启动后台跑 + 屏上显示进度，避免首次点击等待）。
