# Plan: 把架构示意图作为文档资产入库，并让它受既有门禁约束

## 1. Problem

`dsh-token-plan-quota` 的 README 里有 13 张**界面截图**，却没有一张**结构图**。读者想知道
"宿主半边、浏览器半边、只读接口面、五个上游源"之间是什么关系，只能通读三万字。
图已经做好了（Archify architecture 示意图，showcase 档 9/9 通过、四档桌面尺寸无溢出），
现在要决定它**以什么形态入库、放在哪、入库后靠什么守住**。

## 2. Non-goals

- 本次**不会**改 `lib/` 与任何运行时行为——零行为变更是本轮的硬边界。
- 本次**不会**新建独立门禁进程（第 10 项清单加一条即可；新建进程会引入 003 踩过的
  "入口判定静默不执行"那一类风险，收益不匹配）。
- 本次**不会**把 642 KB 的交互式 HTML 交付物入库，**也不会**从它里面抽 SVG 重做矢量版
  （理由见 §3 前提 2 与 §4）。
- 本次**不会**动 `docs/images/` 下已发布的 13 张截图，也**不会**动截图流水线脚本。
- 本次**不会**改 `CHANGELOG.md`、`reviews/`、宪法版本号，也**不会**新增任何依赖。
- 本次**不会**做发布动作（版本号与 npm 发布归 `scripts/release.mjs` 的流程）。

## 3. Premises

| # | 前提 | 怎么核 | 结论 |
|---|---|---|---|
| 1 | 交付 HTML 里是**静态**的单个 `<svg viewBox="0 0 1370 684">`（22,860 字符），不是运行时拼出来的 | 用 node 数 `<svg>` 块并打印片段 | ✅ |
| 2 | 该 SVG 用页面 CSS 类着色（`class="m-default"` 等）、**自身不含 `<style>`** ⇒ 直接抽出来会丢配色与字体 | 同一次输出（`class=` 有、`<style` 无） | ✅ 所以走位图，不抽 SVG |
| 3 | Archify **没有 CLI 导出子命令**，导出是查看器里的按钮 ⇒ 位图不能靠工具命令产出 | 读技能 `bin/` 的子命令与 delivery 契约 | ✅ 所以自己截 |
| 4 | `docs` 在 `package.json#files` 白名单内 ⇒ README 用相对路径引用 `docs/…` 能过"链接目标必须随包发布"那一条 | 读 `package.json` 的 `files` | ✅ |
| 5 | `check-docs` 第 10 项是**硬编码清单**（13 条截图路径）⇒ 新增资产不会被自动纳入断言 | 读 `scripts/check-docs.mjs` 第 10 项 | ✅ 所以要显式加一条 |
| 6 | 本机**没有 Chrome、有 Edge（Chromium）** ⇒ 截图必须显式指定可执行文件，且这条前置不能假定别人也有 | `Test-Path` 实测三处常见路径 | ✅ 已实测 Edge 可用 |
| 7 | 图在四档桌面尺寸无溢出，最大档的底部空白带已压到基线附近 | 无头浏览器 CDP 直读 `getBoundingClientRect`（非肉眼估计）：空白 44 / 44 / 44 / 64 px（1440 / 1600 / 1920 / 2048） | ✅ |
| 8 | 源规格与成品都有确定性哈希，事后可核对 | `deliver` 回执：规格 `8615756d…`（4552 B）、成品 `8957056b…`（641,980 B） | ✅ |
| 9 | 上游端点、信封、单位、方向 | **本轮不涉及上游**（纯文档资产），PLAN 第 4 条硬要求不适用 | n/a |

## 4. Approach

### Considered alternatives

| 方案 | 代价 | 为什么不选 / 选 |
|---|---|---|
| A：`docs/architecture.png`（放 `docs/` 根） | 图片分散在两处（`docs/` 根 + `docs/images/`）；`AGENTS.md` 那条规则的边界仍是模糊的 | 不选：能少改两个文件，但把"图片放哪"这件事永久搞乱 |
| B：**`docs/images/architecture.png`** + 把 `AGENTS.md` 的规则写精确 + 第 10 项清单 +1 | 多改 `AGENTS.md` 与门禁各一处 | **选**：图片集中在一处；那条规则的本意是"这 13 张截图不许手改"，写精确之后图与截图各归各的产出方，边界不再靠人猜 |
| C：把整份交互式 HTML（642 KB）入库 | 体积、且它是生成器输出不是资产；`docs/` 会随 npm 包发布 | 不选 |
| D：手绘 / 抽取 SVG 做矢量版 | 保真风险（前提 2），需要重建样式层 | 不选：收益是"更清晰"，代价是一次有风险的重建，而 2× 位图在 README 里已经够清楚 |
| E：只入库图片，不留源规格 | 图变成不可再生成的二进制孤儿 | 不选：违背"可再生成"的项目价值 |

### Chosen approach and why

**B + E 的修正版**：位图进 `docs/images/architecture.png`（随包发布，README 相对链接两处都能渲染），
**源规格与再生成说明进 `diagrams/`**（不在 `files` 白名单内 ⇒ 不进 npm 包，与"截图流水线脚本不进包"
是同一种切法），第 10 项清单加一条守住资产存在性，`AGENTS.md` 那条规则在同一 PR 里写精确。

被推翻的初版思路记在这里：最初想放进 `docs/images/en/` 之类的语言子目录，但它**与语言无关**
（图注才分语言），放进去会让人以为还有一张中文版。另一版思路是把源规格放在 `specs/004-…/` 里，
但那会让"图属于文档资产"变成"图属于这一轮规格"，下一轮改图时找不到它。

## 5. Design

改动的落点（都在文档层，`lib/` 零改动）：

- **资产**：`docs/images/architecture.png`（2× 位图）。README 以相对路径引用。
- **源规格**：`diagrams/dsh-token-plan-quota.architecture.json`（Archify architecture 规格，可编辑）。
- **再生成脚本**：`diagrams/make-diagram-png.mjs`——**复用** `scripts/shots/cdp.mjs` 已导出的
  `launchEdge` / `Cdp` / `PageHandle.shot`（含 `clip.scale`），**不另写一份 CDP 客户端**。
- **再生成说明**：`diagrams/README.md`——写清前置（Archify 技能 + Chromium + 显式指定可执行文件）、
  命令、产出校验（尺寸与哈希）、以及"**改运行时行为时必须复核此图**"这条漂移约束。
- **门禁**：`scripts/check-docs.mjs` 第 10 项的清单加一条路径。
- **规则**：`AGENTS.md` 里 `docs/images/` 那条从"13 张图只能由截图流水线生成"改为
  "**13 张截图**由截图流水线生成；`architecture.png` 由 `diagrams/` 的源规格产出"——
  规则与它所描述的行为在同一次改动内完成（评审清单 Lens 3 会核这一条）。
- **对外文本**：`README.md` 与 `README.en.md` 各加一处引用与同源图注。

**复用检查**：先搜了有没有已经在做这件事的东西——`docs/upstream-contracts.md` 是协议表、
`workflow/PLAN.md` 是流程模板，都不承担"结构总览"；`docs/images/` 全是界面截图。
**更要紧的是别重复造 CDP**：`scripts/shots/cdp.mjs` 已经导出了定位 Edge、起无头浏览器、
连 CDP、按选择器/裁剪区截图（`shot` 支持 `clip.scale`）的整套能力，所以再生成脚本只负责
"读规格 → 渲染 → 校准裁剪 → 落盘 → 自证"这一层编排。没有重复，新增是唯一的。

## 6. Failure modes

- **截图前置不满足**（对方机器没有 Chromium）：再生成会失败。缓解=说明文件把前置写在最前面，
  且**交付物本身已入库**，日常读者不需要再生成；因此**不**把再生成做成门禁。
- **图与代码漂移**（某个上游源后来被删，图还画着它）：位图无法被机械检查核内容。
  缓解=在再生成说明里把"改运行时行为时必须复核此图"写成硬要求，并把它记为已知盲点落 `workflow/PLAN.md`。
- **双语不同源**（只加 `README.md` 一侧）：现有门禁对"声明"是按 zh+en **并集**看的，
  单侧漏加可能不报——这是 003 已记录的同一类边界，本轮**沿用**并如实标注，不假装它被守住了。
- **位图过大**：约定产物 ≤ 400 KB；截图脚本必须打印真实字节数（不达标就降倍率重截，而不是照收）。
- **取证脚本自己失败却看起来像结论**（读回 0 尺寸 / 0 张图 / 空 rect）：脚本必须**显式失败退出**，
  不允许把空数据写成"无溢出"。这是 PLAN 第 6 节"空数据伪装成结论"那条的直接应用。

### 已知盲点（历次 Retro 累积；写计划时必须逐条对一遍）

- **共享时钟 / 相关样本不能乘**：本轮所有测量都是**确定性单次读值**（rect、字节、哈希），
  没有概率性采样，因此不适用；也不能借"概率很小"来为本轮的任何数字背书。
- **取证脚本必须先自证再采信**：截图脚本要打印它加载的 URL、量到的 SVG rect、输出字节与 sha256；
  报告里出现的每个数字都必须能在脚本输出里找到。
- **空数据会伪装成结论**：见上——空 rect / 0 图 / 0 字节一律按失败处理。

## 8. Test plan

**本次确实改动了一处机械检查**（`check-docs` 第 10 项清单 +1），所以按规则必须给行为矩阵与可证伪性：

| 形态 | 期望 | 怎么测 |
|---|---|---|
| 资产存在且非零字节 | **放行** | `node scripts/check-docs.mjs` 绿 |
| 资产被删除 | **报红** | 临时删掉 → 跑一次 → 贴输出 → 恢复 |
| 资产被截成 0 字节 | **报红** | 临时改 0 字节 → 跑一次 → 贴输出 |
| README 相对路径写错 | **报红** | 临时改名 → 跑一次 → 贴输出 |
| 资产挪到**不随包发布**的目录（如 `diagrams/`）而 README 仍指它 | **报红** | 证明"发布面"那条真的在管发布面 |

可证伪的要求：以上每一条都要有**实际输出的红/绿**，不是"读了脚本觉得会红"。

**不需要**新建独立门禁进程，因此 PLAN 第 8 节里"主路径确实跑了"那一条**不适用**；
但本次新增的**截图取证脚本**适用同一精神：它必须在读回空值时失败退出（见 §6）。

回归面：`test/host.mjs` / `test/client.mjs` / `test/guards.mjs` 三套必须仍全绿（本轮不动 `lib/`，
若它们变红说明改动越界了）。**提交前提**是最后一次编辑之后跑出来的 `npm run check` 输出。
